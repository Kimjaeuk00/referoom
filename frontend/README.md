# 레퍼룸 프론트엔드

Vue 3 + Vite 웹 앱. 화면 요구사항은 DEV_02, API 계약은 DEV_01(인증)·DEV_03(라이브러리)·DEV_04(질의·음성)를 따른다. 백엔드 코드는 이 폴더에 없다.

## 실행

```bash
npm install
cp .env.example .env   # 처음 한 번
npm run dev            # http://localhost:5174 (백엔드 CORS 허용 Origin과 같은 포트)
```

`.env`

| 변수 | 기본값 | 설명 |
|---|---|---|
| `VITE_AUTH_URL` | `http://localhost:8080` | 인증서버 |
| `VITE_RAG_URL` | `http://localhost:8001` | RAG·데이터 서비스 |
| `VITE_VOICE_URL` | `http://localhost:8008` | 음성 서비스 |
| `VITE_USE_MOCK` | `true` | `true`면 서버 없이 `src/api/mock`의 응답으로 동작. 실제 API가 준비되면 `false` |

## 목업 모드에서 시험하기

시연 흐름(DEV_05 5.1)과 같게 맞춰 두었다. LoRA·QLoRA는 처음부터 라이브러리에 있다.

- 계정(비밀번호는 아무 값): `minsu`(개발팀 팀원), `admin`(개발팀 관리자), `rnd`(R&D팀 관리자, 빈 라이브러리), `noteam`(팀 없음), `fail`(로그인 실패)
- 초대 코드: `K3F9Q2XA`(플랫폼개발팀), `R7M2PQ4C`(선행연구팀)
- `admin`으로 라이브러리의 **지금 동기화** → DoRA가 들어오고, 첨부 없는 논문 하나는 실패로 남는다
- **주제로 찾기**에서 `VeRA` → 후보를 골라 수집(한 번에 10편까지). 되돌리기는 없고, 삭제한 논문은 Zotero 휴지통에서 복구한다
- 입력창 아래 모드 칩(선행연구·주제·검증)으로 모드를 고른다. 켠 칩을 다시 누르면 꺼져서 튜터가 된다. 마지막 모드는 새로고침해도 유지된다
  - **선행연구**: `parameter-efficient fine-tuning`을 보내면 후보 창이 자동으로 열린다 → 2편 골라 수집 → 비교 답변과 정리표. `라이브러리 안에서만 찾기`를 켜면 창 없이 바로 보낸다
  - **주제**: 왼쪽 목록에서 논문을 1~10편 고르고 보낸다(힌트는 비워도 된다). 논문이 0편이면 보낼 수 없다. 논문 상세의 **이 논문으로 주제 찾기**로도 들어간다
  - **검증**: 원고를 10~3,000자 붙여 넣는다. 첫 전송에 외부 LLM 전송 고지가 뜬다(동의는 이 브라우저에 기억). `DoRA`가 들어 있으면 근거 없음 + **선행연구로 수집하기**가 나온다
- 질문으로 시나리오 고르기(모든 모드 공통): 기본 → LoRA 답변(출처 2개) / "어텐션"·"수식" → 원문 확인 권장 / "DoRA"·"VeRA"(라이브러리에 없을 때)·"없는" → handoff / "503"·"타임아웃"·"401" → 에러 / "느린" → 12초 지연 / "xss" → sanitize 확인
- PDF 파일 이름에 `dup`이 있으면 409, `scan`이 있으면 배치에서 "텍스트 추출 불가"로 실패
- 주제 검색어가 `zzz`면 후보 0건
- 새로고침하면 목업 데이터가 처음으로 돌아간다

## 근거에서 원문 PDF 보기

답변 아래 근거 목록의 **원문 N쪽 보기**와 논문 상세 화면의 **원문 PDF 열기**는 팀 라이브러리에 보관된 원본 PDF를 새 탭에서 그 쪽으로 연다.

- 흐름: `GET /papers/{id}/file`(RAG 서버, 팀 격리)을 Bearer 토큰으로 받아 Blob URL에 `#page=N`을 붙여 연다. 브라우저 내장 PDF 뷰어가 해당 쪽으로 이동하므로 별도 라이브러리는 없다. 구현은 `src/lib/paperPdf.js`(열기)와 `src/composables/usePdfOpener.js`(버튼 상태·오류 토스트).
- 새 탭은 클릭 직후 서버 응답을 기다리기 전에 먼저 연다(기다린 뒤에 열면 브라우저가 팝업으로 막는다). 팝업이 막히면 안내 문구가 뜬다.
- 근거 문장을 PDF 위에 표시(하이라이트)하지는 않는다. 앱 안 패널 뷰어는 아직 없다.
- 서버에 PDF 사본이 없는 논문(색인 전·실패)은 "서버에 원문 PDF가 없어요. 라이브러리를 동기화해 보세요."가 뜬다. 서버는 PDF를 `PDF_DIR`(`rag-service/app/rag/.cache/pdfs/{팀}/{논문}.pdf`)에 보관하므로, 컨테이너로 배포할 때는 이 폴더를 볼륨으로 유지해야 한다.
- 목업 모드에서는 색인된 논문에 한해 8쪽짜리 예시 PDF가 열린다.

## 음성 기능

녹음·재생 composable(`src/composables/useRecorder.js`, `useAudioPlayer.js`)은 음성 담당 파일이다. 두 파일이 있으면 상단 **음성 튜터** 메뉴와 Q&A의 **말로 묻기**·**답변 듣기** 버튼이 켜지고, 없으면 숨겨진다. 기대하는 반환 모양은 `src/lib/voice.js` 맨 위에 적어 두었다.

## 확인

```bash
npm test        # 모드 계약(modes.js)·수준 사다리(levels.js)·동의 기억·토큰·에러 매핑 검사
npm run build
```

## 배포

```bash
docker build -t referoom-web .
```

compose에서는 `web: { build: ./frontend, ports: ["5174:80"] }`. `VITE_*`는 브라우저가 접근하는 주소라서 빌드 인자(`--build-arg VITE_RAG_URL=...`)로 넘긴다. nginx가 모든 경로에 `index.html`을 돌려줘서 새로고침해도 화면 주소가 유지된다.
